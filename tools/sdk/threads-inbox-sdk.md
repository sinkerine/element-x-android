# Threads Inbox SDK integration

Threads Inbox uses `Client.threadInboxPager`, `Client.threadInboxUnread` and `subscribeToThreadInboxUpdates` from the local Matrix Rust SDK fork's `main` branch. Android variants use the same locally built AAR so release compilation cannot silently select the older published bindings.

Build prerequisites: Rust 1.96 or later with the Android target installed, cargo-ndk, JDK 21, Android SDK and NDK. Set `ANDROID_HOME`, `ANDROID_SDK_ROOT`, and `ANDROID_NDK_HOME`. The default authorized checkout is `/home/sinkerine/orca/matrix-rust-sdk`; override it with `THREADS_INBOX_SDK_CHECKOUT` when reproducing elsewhere. The script requires the SDK checkout to be on `main` and pins the Kotlin packaging project to the revision used during verification.

```sh
tools/sdk/build-threads-inbox-sdk x86_64-linux-android
./gradlew :app:assembleGplayDebug
```

Run the SDK script again with `aarch64-linux-android` to add arm64 before building for an arm64 device. The staging directory retains the previously built ABI. The generated AAR and Kotlin packaging checkout are local build artifacts and must not be committed. No publishing or credentials are needed.

Threads lists only threads the user participated in (`threadInboxPager(participatedOnly = true)` sends `include=participated`, so the homeserver filters and every page holds up to 20 such threads). Opening Threads loads the newest 20 of them across joined rooms; the list shows unread threads first, then by latest reply. Threads read during a visit keep their position until the visit ends. There are no tabs, Unread/All filters or latest-unread banner. The SDK cursor fetches one small head page per room with at most eight concurrent requests, merges by latest reply time, and retains unused roots and per-room server cursors. Buffered roots stay raw; only the 20 selected roots are mapped to list items. Each selected root carries the server's bundled `current_user_participated` flag. Older roots are requested only on scrolling near the bottom or tapping Load more; every request returns at most 20 unique threads. Existing Matrix thread-list endpoints are used; no homeserver deployment is needed. A failed request leaves the cursor unadvanced for retry.

Android classifies rows without timelines. Participation comes from the bundled summary. A row is read without any request when its latest reply is the user's own or covered by a stored threaded receipt, or when it has no replies. Only unread rows call `threadInboxUnread`, which pages `/relations` backwards (100 per request, at most eight threads concurrently) and stops at the newest receipt or own reply, so it never pages to the root unless there is no boundary. A scan is capped at 300 replies; capped counts and mentions are lower bounds and are logged. Each row is published as soon as it is classified. A failed row leaves the others visible, fails the batch, and is retried with the retained batch. Opening an unread thread reuses the scan's first unread reply; only a capped thread falls back to loading its threaded timeline. Success describes the loaded batch, not an exhaustive account snapshot. There are no numeric tab badges or closed-inbox badge scans. Mark loaded threads as read affects only loaded matches.

Sync updates mark the cursor dirty for the next visit; they do not start background scans. A warm unchanged visit retains its loaded rows. Undecryptable replies count as unread but cannot be recognised as mentions. Matrix provides per-room ordering rather than an atomic account-wide snapshot; concurrent server changes can affect ordering between pages.
